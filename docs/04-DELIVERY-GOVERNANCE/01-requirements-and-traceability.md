# G-01 — REQUIREMENTS & TRACEABILITY
**Version:** 0.1 · **Status:** DRAFT · **Owner:** Product/BA
Requirement lifecycle: Proposed → Analyzed → Approved → Implemented → Verified → Accepted → Baselined. Post-baseline change requires change request and impact analysis.
ID convention: BR/NFR for business/nonfunctional; CUS/BKG/FLT/PRT/DSP/DRV/TRP/FAR/PAY/FIN/SET/CT/CS/IAM/AUD/INT/RPT for feature IDs.
Traceability: Business goal → requirement → E2E step → Module → Feature → UI state → API/command/event → data entity/rule → test → acceptance evidence → release.
Requirement record: ID, statement, rationale, source, priority, owner, acceptance, dependencies, assumptions, decision refs, status, version, change history.
Quality: no orphan requirement, no unowned decision, no feature without acceptance, no API without permission/error/idempotency, no critical workflow without negative/concurrency/recovery tests.
